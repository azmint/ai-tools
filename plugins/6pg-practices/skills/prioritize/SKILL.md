# 優先度付け

各軸を **高 / 中 / 低** で見て、判定表で結果を決める。点数の掛け算にはしない（同点と、見せかけの精度を生むため）。判定表の結果は候補の絞り込みであり、最終順位は同じ帯の中で比べて 1 列に並べる（スタックランキング）。

## 項目を揃える

- 材料を自分で集める場合は、環境で使えるものから読み取りで集め、集めた範囲を一行で書く。
- 同じ対応で片付くものは 1 項目にまとめる。似た小項目（古い Issue 群など）は 1 行にまとめてよく、行の中の順位は要らない。
- 文書の主張を確かめずに使った場合は、根拠に「未検証」と添える。
- 判定できない軸は「?」とする。重大度では高、機会の価値では低と仮に置いて判定し、結果に「（仮）」と添える（着手順での扱いは「着手順」の手順 2）。
- 外部の深刻度ラベル（CVSS、Dependabot の critical など）は参考にとどめ、深刻度はこの環境で届くかどうか（本番に載るか、悪用の経路があるか）で決める。

項目ごとに、下の 3 つの判定から当てはまるものを使う。高をさらに一段上げる場合は高のまま。

## 問題の重大度（バグ・障害・リスク・ふりかえりの Bad）

FMEA の Action Priority の考え方で、深刻度を最優先する。

- **深刻度**: 誰にとってどれだけ悪いか。最も重い立場で決め、その立場を根拠に書く
- **発生**: 頻度と波及の広さ。今後の見込みで見る。既定は直近の実績（過去 3 か月程度の頻度）とし、予定しているリリースやロードマップが分かればそれで補正する。根拠に「推定（直近 3 か月の実績から）」のように書く。実績も予定もない新しいものだけ「?」にする。頻度が低くても、1 回あたりが重い・手順を忘れやすいものは、深刻度と検出のしにくさで拾う
- **検出のしにくさ**: 起きても気づけない度合い。確かめるべきことを確かめておらず監視もなく、利用者も気づきにくいなら高。日常の利用者がすぐ気づけるなら中（気づくのが利用者頼みなので低にはしない）。確認や監視で早く分かるなら低

| 深刻度 | 結果 |
|---|---|
| 高 | 発生か検出が中以上なら **高**、両方とも低なら **中** |
| 中 | 発生・検出とも高なら **高**、どちらかが中以上なら **中**、両方とも低なら **低** |
| 低 | **低** |

- 後始末（使われない PR・失敗し続ける CI・古い設定の片付けなど）も問題として扱い、深刻度は残したときの害で決める（本物の失敗がノイズに埋もれる、誤解や費用を生む）。害が小さく急がないものは個別に判定せず、似たものを 1 項目に束ねて「定期枠」に回す（P は付けない）。次に棚卸しする日か件数のしきい値を書き、そのチケットか予定を差し込む案を出して、承認を得て登録する。
- 利用者が理由とともに明示的にリスクを受け入れたものは、結果はそのまま付け、受け入れた判断を根拠に記す。その判断の質（当時の情報で妥当だったか）は別に問う。

## 機会の価値（改善案・続けたいこと・ふりかえりの Good）

- **効果**: 続けた・広げたときに、誰にとってどれだけ効くか。効く回数は今後の見込みで見る
- **再現性**: 運ではなく条件で説明できるか（確信度）。条件が記録や仕組みに残っているかは、ここではなく下の「一段上げる」で見る

| 効果 ＼ 再現性 | 高 | 中 | 低 |
|---|---|---|---|
| 高 | 高 | 高 | 中 |
| 中 | 中 | 中 | 低 |
| 低 | 低 | 低 | 低 |

- 仕組み化しないと失われるものは一段上げる。

## 着手順（タスク・バックログ・次の行動）

Cost of Delay ÷ 所要期間（WSJF / CD3）の考え方。遅らせたときの損失が大きく、早く終わるものから着手する。項目ごとに次の順で当てはめ、決まったところで止める。

1. **進行中の障害か**: 重大度が高く進行中・期限内のもの、またはほかの作業を止めているものは **P0**（表より優先）。進行中かどうか確認しないと分からないものは、確かめる作業を P1 の先頭に置き、「確認で障害なら P0」と添える。
2. **判定に足りない情報があるか**: 価値などが「?」なら、確かめる作業（時間を区切った調査）を別の項目として判定し、元の項目は P3（要再判定）にする。
3. **後始末で、害が小さく急がないか**: 「定期枠」に束ねる（問題の重大度の節）。
4. 残りを下の判定表で P1〜P3 にする。

Cost of Delay は次の 3 つを 高/中/低 で見る。高が 2 つ以上なら **高**、高が 1 つか中が 2 つ以上なら **中**、それ以外は **低**（例: 高・低・低 → 中、中・低・中 → 中、中・低・低 → 低）。

- **価値**: 問題なら重大度、機会なら機会の価値の結果を使う。複数の事象にまたがる行動は、最も高いものを使う
- **時間的切迫度**: 遅れるほど価値が減る、または損失が増える。高 = 期限や次に起きる時点（次のリリースなど）が近い、または進行中の損失がある。中 = 放置すると数か月で積み上がる・広がる・直しにくくなる（競合や手戻りが増える、関係者の記憶が薄れる、など）。低 = いつやっても結果が変わらない
- **波及**: 価値に数えていない別のリスクを減らす、またはほかの作業を可能にする（同じリスクを二重に数えない）。高 = 複数の作業の前提になっている、または止めている。中 = 1 つの作業の前提になる、または同じ変更で別の問題も片付く。低 = それ単独で閉じる

所要期間は、人のレビューや本番への適用まで含めた完了までの期間で、小（1 日以内）/ 中（1 週間以内）/ 大（それ以上）。推定なら根拠に「推定」と添える。

| Cost of Delay ＼ 所要期間 | 小 | 中 | 大 |
|---|---|---|---|
| 高 | P1 | P1 | P2（分割して再判定） |
| 中 | P1 | P2 | P2 |
| 低 | P2 | P3 | P3 |

- P1 は多くても 5 件程度。超えたら比べて下位を P2 に回す。
- 区分の意味: P0 = 今すぐ / P1 = この期間内 / P2 = 余裕があれば / P3 = 保留（後回し）・要再判定（? が残る）・却下（クローズ候補）。P3 にはどれかと理由を書く。定期枠 = 順位を付けず、決めた日かしきい値でまとめて片付ける。

## 出力

ほかのスキルから判定だけを求められたとき（ふりかえりの深さ決めなど）は、項目ごとの結果（高・中・低）と一言の根拠を返すだけでよい。同じ帯の中の並べ替えはせず、出力の形は呼び出し元に従う。単独で使うときは次の形で出す。

1. 集めた範囲（自分で集めた場合だけ、一行）
2. 表を 1 つ。結果の帯ごとに並べ替えた順で載せ、定期枠は最後に 1 行（次の棚卸しの日かしきい値と、登録の案）。確認して除外した項目は表の下に一行で書く。複数の判定を使う項目は、各軸の欄に「重大度: 深刻度 高・発生 中・検出 高 → 高 / CoD 中・期間 小」のように順に書く

| 項目 | 判定 | 各軸 | 結果 | 根拠 |
|---|---|---|---|---|

3. 並べ替えの理由（同じ帯の中で順位を決めた理由を一言ずつ）
4. 最初の一手（着手順を判定したときだけ、一行）

完了条件: すべての項目に結果と一言の根拠があり、同じ帯の中の順位が決まっている。
